# 统一票务界面（1.1.0）

## 实现

- 六个公共入口：首页、扫码登录、任务列表、创建任务、票务查询、通知配置。
- 携程、去哪儿、12306 独立登录卡片；二维码独立刷新、过期和轮询，确认登录后留在原页。
- 查询及创建页切换火车票 / 机票，创建表单通过 KeepAlive 保留各自草稿；查询条件可以带入创建表单。
- 任务适配层保留两套业务接口和数据库表，统一标识为 `rail:{id}` / `flight:{id}`，详情、编辑、控制动作按类型分发。
- 首页分开统计机票预算达标及订单待支付；列表展示平台、行程、执行进展、最近报价和订单结果。
- `GET /flights/providers/{provider}/session` 查询本机会话；`PATCH /flights/monitors/{id}` 编辑已暂停任务并清除旧核对结果。
- 平台重新扫码使用隔离会话，确认替换前保留旧会话，替换前暂停对应平台活动任务。加密会话仍存放于原用户数据目录。
- 通知渠道共用，按票种订阅事件；桌面通知配置通过本机认证访问。旧配置保留兼容，渠道组件只接收渠道参数。
- 任务结果与通知事件在同一数据库事务中保存；运行批次及通知出站记录持久化，发送失败独立重试，已成功渠道不重复发送。
- 数据迁移仅新增表 / 列；保留旧任务、账号、通知配置、订单尝试。旧火车票链接及 `/flights`、`--flights` 继续兼容。

## 验证

- 自动化覆盖：旧数据库增量迁移、两类同编号任务、操作状态、暂停后编辑、平台账号替换、通知订阅、失败重试、渠道部分成功及重启去重、响应式请求的桌面 IPC 序列化。
- 本机联调：12306 扫码后保持当前页；三平台会话恢复；北京至上海 2026-11-06 查询、携程 / 去哪儿选舱及预订核对。
- 查询结果带入机票创建表单，票种切换后各自草稿保留；价格升序、时间降序及手动下单按钮随核对结果启用。
- 两类任务创建、启动、暂停及重启恢复；重启后沿用原通知批次。火车票自动提交关闭，机票使用核对或参考报价方式。
- 使用本地模拟 Webhook 验证事件发送。页面“测试发送”支持选择两种票务样例。
- 安装包沿用 `com.12306.ticket-helper` 和原用户数据目录；后端资源与构建结果逐文件校验，内含数据仅车站静态资源。
